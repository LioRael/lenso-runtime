# Native service → explicit wire boundary

Source map: `PROTOCOL.md`, `tools/generate.ts`, `examples/contracts/logs.json`, `examples/generated/logs.{ts,rs}`, `sdk/typescript/index.ts`, `crates/sdk/src/lib.rs`. Read the method/schema section needed, not the full protocol for an ordinary service change.

The executable baseline is schema-first at the **wire boundary**. A restricted JSON Schema contract describes version/method mode/input/output/error. Run the actual generator:

```sh
bun tools/generate.ts examples/contracts/logs.json examples/generated logs
```

This creates TS and Rust bindings, including `LogsClient` and Rust `LogsServer`. A developer-authored native function remains the business implementation. JSON can be generated by a higher-level authoring tool; it is not a mandatory manually maintained language for every local method. Source-first/authoring integration is separate in-progress work unless the consuming checkout demonstrably includes it. Do not invent decorators, reflection, derive macros or `exportAll` APIs.

## Preserve these semantics

- Types do not replace boundary validation. Generated clients validate caller input/output/business-error/stream item constraints; the kernel also validates boundaries. Rust low-level `call`/`stream` only deserialize; prefer generated clients or actual `call_contract`/`stream_contract` APIs.
- Optional non-null and required nullable fields are supported. Optional **nullable** fields are rejected in v1. Missing, null and JS undefined are different; omit optional fields instead of sending undefined. Rust `Option` alone may not represent every desired missing/null distinction.
- Integers use canonical JSON integer tokens in the JavaScript safe range. Rust `u64/i64`, JS bigint, NaN/Infinity, Dates, bytes, errors, functions, Arc, DB connections and transactions do not automatically serialize into a valid contract. Use explicit bounded data, safe numbers/strings, or owner-controlled storage references.
- Do not turn private native errors into arbitrary message strings. Distinguish declared business errors from transport/schema/timeout/overload/disconnect failures. Preserve internal causes; expose only approved codes and declared safe data.
- Streams must remain bounded end to end. TS uses async iterators; Rust handlers await `StreamSender::send`. Do not collect an unbounded stream or spawn unbounded producers ahead of credit. Await/consume completion and final cleanup, not just the first item.
- Cancellation and deadlines can race completed mutations. Reconnect does not replay. No automatic retry, exactly-once, distributed transaction or persistent queue is provided.

Forward TS nested calls with `{ traceId: context.traceId, parentId: context.callId, signal: context.signal }`. Rust exposes `trace_id`, `call_id`, `cancellation`; use the generated client's actual options type. A JS handler ignoring abort retains its execution slot until its Promise/iterator cleanup settles; cancellation is not preemption. Dropping a Rust future also does not reverse already committed effects.

Keep credential/session/actor objects in their owning process. Connection-bound service names identify trusted local processes but are not authenticated users. Never authorize a Rust resource from a TS actor serialized into business JSON.
